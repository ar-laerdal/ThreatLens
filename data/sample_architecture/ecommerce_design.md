# ShopFast - E-Commerce Platform: Architecture Design Document

Version 1.2 (sample document for the ThreatLens demo)

## 1. Overview
ShopFast is an online retail platform. Customers browse products, sign in, place orders and pay by card.
Order confirmations are sent by email and SMS.

## 2. Components

### 2.1 Web Frontend (Internet-facing)
Single-page application (React) served from a CDN. Runs in the customer's browser. Stores the access token
in browser local storage. Talks only to the API Gateway.

### 2.2 API Gateway (DMZ)
Public entry point for all API traffic (`/api/v1/*`). Terminates TLS, applies a global rate limit of
1000 requests/minute per source IP, validates JWT access tokens issued by the Authentication Service, and
routes requests to the Application Backend. Cross-origin requests are allowed from `*.shopfast.example`.

### 2.3 Authentication Service (Internal)
Handles registration, login (email + password), password reset and token issuance. Issues JWT access tokens
(60 minute lifetime) and refresh tokens (30 days). Password hashes are stored in the User Database.
Multi-factor authentication is not currently offered to customers. Administrators sign in through the same
service.

### 2.4 Application Backend (Internal)
Python service exposing REST endpoints for products, carts, orders and user profiles:
- `GET /orders/{orderId}` returns an order by ID
- `POST /orders` creates an order
- `PUT /users/{userId}/profile` updates a profile
- `POST /admin/products` creates or edits products (admin role)
Order and profile data is read and written in the User Database. Product images and invoices (PDF) are
read from and written to Object Storage. The backend runs as a single service account with read/write
access to both the database and the storage bucket.

### 2.5 User Database (Internal)
PostgreSQL. Stores customer accounts (name, email, phone, shipping address, password hash), orders and order
history. No card numbers are stored. Database credentials are provided to the backend through environment
variables. Backups are taken nightly.

### 2.6 Payment Gateway (Third-party)
External PCI-DSS certified provider. The frontend sends card details directly to the provider's hosted
fields and receives a payment token. The backend submits the token and order amount to the Payment Gateway
over HTTPS and receives a payment result through a webhook endpoint on the API Gateway
(`POST /webhooks/payment`).

### 2.7 Object Storage (Internal cloud storage)
S3-compatible bucket holding product images (public read) and customer invoices (private). Invoices are
downloaded through pre-signed URLs generated by the backend.

### 2.8 Notification Service (Third-party)
External email/SMS provider. The backend sends the customer's name, email, phone number and order summary
to the provider's REST API using a static API key.

## 3. Data flows
| # | From | To | Data | Protocol |
|---|------|----|------|----------|
| 1 | Web Frontend | API Gateway | Login, product, cart and order requests | HTTPS |
| 2 | API Gateway | Authentication Service | Credentials, token validation | HTTP (internal network) |
| 3 | API Gateway | Application Backend | Authenticated API requests | HTTP (internal network) |
| 4 | Authentication Service | User Database | Account records, password hashes | TLS |
| 5 | Application Backend | User Database | Orders, profiles | TLS |
| 6 | Application Backend | Object Storage | Product images, invoices | HTTPS |
| 7 | Web Frontend | Payment Gateway | Card details (hosted fields) | HTTPS |
| 8 | Application Backend | Payment Gateway | Payment token, amount | HTTPS |
| 9 | Payment Gateway | API Gateway | Payment result webhook | HTTPS |
| 10 | Application Backend | Notification Service | Customer contact details, order summary | HTTPS |

## 4. Trust boundaries
- Internet (customers, attackers) | DMZ (API Gateway)
- DMZ | Internal network (Authentication Service, Application Backend, User Database, Object Storage)
- Internal network | Third-party services (Payment Gateway, Notification Service)

## 5. Sensitive data
Customer PII (name, email, phone, address), password hashes, JWT/refresh tokens, order history, invoices,
payment tokens, and third-party API keys.

## 6. Operational notes
- Audit logging: the API Gateway keeps access logs for 7 days. The Application Backend does not log
  administrative actions.
- Webhook requests from the Payment Gateway are accepted if they contain the expected JSON structure.
